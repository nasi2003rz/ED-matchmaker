## ۱. وضعیت فعلی (Audit)

### چه چیزی هست
- **استک:** Next.js 16 (App Router) + Tailwind v4 + کامپوننت‌های سبک shadcn/base-ui، فونت `Vazirmatn`، کل اپ `dir="rtl"` و `lang="fa"`، PWA با Serwist.
- **توکن‌های طراحی** در `frontend/src/app/globals.css`: رنگ اصلی سبز-آبی (teal `oklch(0.6 0.118 184.704)`)، رنگ‌های معنایی `success / warning / info / destructive` + `-foreground`، مقیاس `--radius`، و توکن‌های `sidebar-*` (تعریف‌شده ولی **بدون استفاده**).
- **کامپوننت‌های UI موجود:** `avatar, badge, button, card, checkbox, dialog, dropdown-menu, input, label, select, separator, skeleton, sonner (toast), table, tabs, textarea` + `class-form`, `role-picker`.
- **صفحات موجود:** `/` (خوش‌آمد/انتخاب نقش + چند لینک)، `/login`، `/register`، `/onboarding/instructor`، `/classes`، `/classes/new`، `/classes/[id]`، `/students`، `/join/class/[id]`، `/style-guide` (موقت).
- **الگوهای تثبیت‌شده:** Client Component + `useAuth`، گیت دستی توکن با `router.replace`، `toast` برای خطا، `Skeleton` برای بارگذاری، Empty State درون‌خطی، برچسب وضعیت با `Badge`.
- گام‌های ۱ تا ۹ فهرست اجرای CLAUDE.md §12 عملاً انجام شده‌اند (تا Invitations).

### شکاف‌های ساختاری (باید در این پلن حل شوند)
1. **هیچ App Shell / ناوبری‌ای وجود ندارد.** هر صفحه یک `div` وسط‌چین با `max-w-*` و `dir="rtl"` تکراری است. نه Bottom Nav، نه Header، نه Sidebar — یعنی ناوبری «۵ تبه» بخش ۷ اصلاً پیاده نشده.
2. **فقط نقش INSTRUCTOR رابط دارد.** دانش‌آموز و والد هیچ صفحه‌ای جز `join` و انتخاب نقش ندارند.
3. **حالت تاریک عملاً غیرفعال است.** `next-themes` فقط در `sonner.tsx` import شده؛ `ThemeProvider` در `layout.tsx` نیست و هیچ‌جا کلاس `.dark` ست نمی‌شود.
4. **هیچ Layout Primitive مشترکی نیست** (عرض صفحه، پدینگ، عنوان صفحه، اکشن هدر همه کپی‌پیست‌اند).
5. **داشبورد مربی خالی است** — صفحه‌ی `/` فقط لینک است، نه ویجت‌های بخش ۷ (کلاس‌های امروز، شهریه‌ی پرداخت‌نشده، پیام خوانده‌نشده…).
6. صفحه‌ی `/style-guide` موقت است و باید جای خود را به مستند سیستم طراحی + صفحه‌ی زنده‌ی کامپوننت‌ها بدهد.

## ۳. سیستم طراحی (Design System)

### ۳.۱ رنگ
توکن‌های فعلی `globals.css` **حفظ می‌شوند**. تغییرات:

- **رنگ اصلی (teal):** برای اکشن اولیه، لینک‌ها، حالت فعال ناوبری، حلقه‌ی فوکوس. تنها رنگ «برند».
- **رنگ‌های معنایی** فقط برای وضعیت، نه تزئین:
  - `success` → حاضر / پرداخت‌شده / تأییدشده / تکلیفِ بررسی‌شده
  - `warning` → تأخیر / پرداخت جزئی / سررسید نزدیک / تکلیف دیرکرد
  - `destructive` → غایب / پرداخت‌نشده-سررسیدگذشته / لغو / حذف
  - `info` → موجه / اطلاع‌رسانی خنثی / زمان‌بندی تغییر کرد
  - `muted` → پیش‌نویس / بایگانی / در انتظار
- **افزودن:** یک نگاشت مرکزی `status → {token, label, icon}` در `src/lib/status.ts` تا رنگ/برچسب وضعیت‌ها در حضور، پرداخت، تکلیف و کلاس یک‌جا مدیریت شود (جلوگیری از پراکندگی فعلی در `classes-labels.ts`).
- **حالت تاریک:** بلوک `.dark` کامل است؛ فقط باید فعال شود (بخش ۳.۶).

### ۳.۲ تایپوگرافی
- فونت: `Vazirmatn` (هست). وزن‌ها: 400 متن، 500 نیمه‌تأکید، 600 عنوان کارت/سکشن، 700 عنوان صفحه.
- مقیاس (موبایل): عنوان صفحه `text-xl/bold`، عنوان بخش `text-lg/semibold`، عنوان کارت `text-base/semibold`، متن `text-sm`، فرعی `text-xs text-muted-foreground`. دسکتاپ یک پله بزرگ‌تر برای عنوان صفحه.
- اعداد: کامپوننت `<Num>` برای نمایش فارسی (`toLocaleString('fa-IR')`) + واحد («تومان»، «نفر»، «جلسه»). ساعت و تلفن با ارقام لاتین باقی می‌مانند.
- `line-height` سخاوتمند برای خوانایی فارسی (`leading-7` در متن‌های بلند).

### ۳.۳ فاصله‌گذاری و شعاع
- شبکه‌ی ۴px. فاصله‌ی استاندارد بین بخش‌های صفحه `space-y-6`، درون کارت `space-y-3`.
- `--radius: 0.625rem` (هست). کارت‌ها `rounded-lg`، ورودی/دکمه `rounded-md`، Badge `rounded-sm`.
- سایه‌ی حداقلی؛ تفکیک با `border` (مطابق الگوی فعلی).

### ۳.۴ آیکون
- `lucide-react` (هست). اندازه‌ی پیش‌فرض `size-4` درون‌خطی، `size-5` در ناوبری، `size-6` در حالت خالی/کارت نقش.
- ست ثابت ناوبری: `LayoutDashboard, GraduationCap (کلاس), Users (دانش‌آموز), Calendar, MessageCircle, MoreHorizontal, CreditCard, ClipboardCheck (حضور), BookOpen (تکلیف)`.

### ۳.۵ Layout Primitives (افزودنی — پایه‌ی رفع شکاف ۱ و ۴)
سه کامپوننت جدید در `src/components/layout/`:

1. **`<AppShell>`** — پوسته‌ی احرازشده: ناوبری واکنش‌گرا (Bottom Tab در موبایل، Sidebar در دسکتاپ ≥ `lg`)، Header نازک با عنوان صفحه + اکشن، ناحیه‌ی محتوا با `max-w` و پدینگ استاندارد، `<Toaster>`. سوییچ نقش فعال هم اینجاست.
2. **`<PageHeader title actions? back?>`** — عنوان صفحه + دکمه‌ی اکشن اولیه + دکمه‌ی بازگشت (با آیکون mirror-شده‌ی RTL).
3. **`<Section title? action?>`** — بلوک محتوایی با عنوان اختیاری؛ جایگزین `div`های دست‌ساز فعلی.

الگوهای کمکی: `<EmptyState icon title description action?>`, `<StatCard label value hint? tone?>`, `<ListSkeleton rows?>`, `<ErrorState onRetry>`.

### ۳.۶ حالت تاریک و RTL (رفع شکاف ۳)
- افزودن `ThemeProvider` از `next-themes` در `layout.tsx` با `attribute="class"`, `defaultTheme="system"`.
- سوییچ تم در تب «بیشتر» هر نقش (سه‌حالته: روشن/تاریک/سیستم).
- `layout.tsx` همچنان `dir="rtl"` روی `<html>`؛ **حذف `dir="rtl"` تکراری از تک‌تک صفحه‌ها**.
- چک‌لیست RTL: `ms-*/me-*` به‌جای `ml-*/mr-*`، آیکون‌های جهت‌دار با `rtl:-scale-x-100`، اسلایدر/چارت‌ها آینه‌ای، `text-start/text-end`.

### ۳.۷ صفحه‌ی زنده‌ی سیستم طراحی
`/style-guide` فعلی → به `/design-system` ارتقا و گسترش: پالت، تایپوگرافی، همه‌ی توکن‌های وضعیت، Layout Primitives، حالت‌های Loading/Empty/Error، نمونه‌ی هر کامپوننت در روشن/تاریک. فقط برای توسعه (پشت گیت محیط).

## ۴. معماری اطلاعات و ناوبری (IA + Navigation)

### ۴.۱ App Shell واکنش‌گرا
- **موبایل (< `lg`):** Bottom Tab Bar ثابت، ۵ آیتم، برچسب فارسی زیر آیکون، آیتم فعال با رنگ اصلی. Header بالای صفحه: عنوان + اکشن اولیه.
- **دسکتاپ (≥ `lg`):** Sidebar راست (چون RTL) با همان آیتم‌ها + برچسب، آواتار و نقش فعال در بالای Sidebar. محتوا `max-w-4xl`.
- **تب «بیشتر»:** پروفایل، تغییر/افزودن نقش، سوییچ نقش فعال، تم، مؤسسه (مربی)، خروج، نسخه/نصب PWA.

### ۴.۲ ناوبری هر نقش (مطابق CLAUDE.md §7)

| نقش | تب‌ها |
|---|---|
| **مربی** | داشبورد · کلاس‌ها · دانش‌آموزان · تقویم · پیام‌ها · بیشتر |
| **دانش‌آموز** | خانه · کلاس‌های من · تقویم · تکالیف · پیام‌ها · بیشتر |
| **والد** | خانه · فرزندان · تقویم · پیام‌ها · بیشتر |

اگر کاربر چند نقش دارد: سوییچر نقش فعال در Header/Sidebar؛ ناوبری با نقش فعال عوض می‌شود (نه ادغام تب‌ها).

### ۴.۴ گیت نقش

## ۵. الگوهای تعامل (Interaction Patterns)

### ۵.۱ چهار حالت هر نما
هر لیست/نما باید صریحاً این‌ها را داشته باشد (مطابق CLAUDE.md §13):

| حالت | الگو |
|---|---|
| **Loading** | `<ListSkeleton>` هم‌شکل با محتوای نهایی (نه اسپینر تمام‌صفحه). پوسته‌ی ناوبری بلافاصله رندر می‌شود. |
| **Empty** | `<EmptyState>` با آیکون + یک جمله + دکمه‌ی اکشن سازنده (مثلاً «اولین کلاس را بساز»). لحن تشویقی، نه خطا. |
| **Error** | `<ErrorState onRetry>` درون‌خطی برای خطای بارگذاری؛ `toast.error` برای خطای اکشن. پیام فارسی قابل‌فهم از `ApiError.message`، بدون کد فنی. |
| **Success/Content** | محتوا + در صورت لزوم Optimistic Update (مثل toggle آرشیو فعلی). |

### ۵.۲ فرم‌ها
- برچسب همیشه بالای فیلد، `Label` مرتبط با `id`. خطا زیر فیلد با `text-destructive text-xs` + `aria-describedby`.
- اعتبارسنجی با `zod` (هست) هم‌زمان سمت کلاینت و سرور؛ پیام‌های فارسی در schema.
- دکمه‌ی ثبت: متن حالت در حال ارسال («در حال ذخیره...») + `disabled`. یک اکشن اولیه، «انصراف» ثانویه.
- فرم‌های بلند (ساخت کلاس، Onboarding) → تک‌ستونه، گروه‌بندی با `<Section>`؛ در صورت رشد، Stepper با ذخیره‌ی پیش‌نویس.
- فیلدهای اختصاصی دسته (CLAUDE.md §5.5): رندر داینامیک از `CategoryFieldDefinition` (`TEXT/NUMBER/BOOLEAN/SELECT/DATE`) در یک `<CategoryFieldsFieldset>`.

### ۵.۳ لایه‌بندی روی صفحه
- **Dialog** (هست): تأیید کوتاه، فرم تک‌فیلدی (مثل «افزودن دانش‌آموز»).
- **Sheet/Drawer** (افزودنی، از پایین در موبایل): فرم‌های ۲–۵ فیلدی مثل ثبت پرداخت، دادن نمره، پیشنهاد جلسه‌ی خصوصی.
- **صفحه‌ی کامل:** جریان‌های چندمرحله‌ای یا داده‌ی سنگین.
- **`AlertDialog`** (افزودنی): فقط برای اکشن‌های مخرب/غیرقابل‌بازگشت (حذف کلاس، لغو ثبت‌نام، باطل‌کردن لینک دعوت).

### ۵.۴ بازخورد و اعلان
- `toast` (Sonner، `top-center`, `dir=rtl`) برای نتیجه‌ی اکشن.
- Badge شمارنده روی تب «پیام‌ها» و آیکون اعلان.
- مرکز اعلان درون‌اپ (CLAUDE.md §5.2): Sheet از آیکون زنگ در Header؛ رویدادها: دعوت، تکلیف جدید، تکلیف بررسی‌شد، نمره‌ی جدید، یادآوری کلاس، تغییر برنامه، پیام جدید، یادآوری پرداخت. سرویس مشترک `notifications`، جداکوپل از ماژول‌ها.

## ۶. مشخصات صفحه‌به‌صفحه (به‌ترتیب گام‌های CLAUDE.md §12)

> برای هر صفحه: هدف · اجزای کلیدی · اکشن اولیه · حالت خالی. طراحی wireframe سطح پایین؛ جزئیات بصری از سیستم طراحی می‌آید.

### ۶.۱ Onboarding مربی (گام ۶ — موجود، نیازمند پولیش)
- **هدف:** از ثبت‌نام تا «داشبورد با اولین کلاس» در < ۳ دقیقه.
- **جریان هدف:** register → انتخاب نقش (اگر لازم) → «بسازیم اولین کلاس شما را» (فرم کوتاه) → صفحه‌ی موفقیت با **لینک دعوت آماده‌ی کپی** → داشبورد.
- پروفایل کامل مربی‌گری (تلفن، دسته، بیو، تجربه، شهر) **اختیاری و مؤخر**؛ نмایش به‌صورت Nudge کارت در داشبورد (الگوی `InstructorProfileNudge` فعلی حفظ شود).
- حالت خالی داشبورد جدید مربی = همین CTA ساخت کلاس.

### ۶.۲ داشبورد مربی (گام ۱۶ منطق، ولی ساخت زودتر لازم است)
- **هدف:** «امروز چه دارم؟»
- **ویجت‌ها (کارت، به‌ترتیب اولویت موبایل):**
  1. کلاس‌های امروز (زمان، نام، تعداد حاضر/کل) + دکمه‌ی «ثبت حضور»
  2. `<StatCard>`های ردیفی: تعداد دانش‌آموز فعال · تکلیف‌های در انتظار بررسی · شهریه‌ی پرداخت‌نشده · پیام خوانده‌نشده
  3. جلسات پیش‌روی این هفته
  4. Nudge تکمیل پروفایل (شرطی)
- اکشن اولیه‌ی Header: «کلاس جدید».
- حالت خالی: بدون کلاس → CTA ساخت کلاس؛ با کلاس بدون دانش‌آموز → CTA دعوت.

### ۶.۳ کلاس‌ها (گام ۸ — موجود)
- لیست کارتی (هست): نام، Badge وضعیت، زمان‌بندی، «X از Y نفر — Z صندلی خالی» (از داده‌ی واقعی `Enrollment`، CLAUDE.md §8.2).
- افزودن: فیلتر وضعیت (فعال/پیش‌نویس/تمام‌شده/بایگانی)، جست‌وجوی نام.
- اکشن اولیه: «کلاس جدید». حالت خالی موجود، فقط با `<EmptyState>` استاندارد شود.

### ۶.۴ ساخت/ویرایش کلاس (گام ۸ — موجود)
- فرم تک‌ستونه با `<Section>`: پایه (نام، دسته، توضیح) · نوع (خصوصی/گروهی، آنلاین/حضوری، شهر) · زمان‌بندی (روزها، ساعت، تاریخ شروع/پایان، تعداد جلسات) · ظرفیت و شهریه · فیلدهای اختصاصی دسته (داینامیک).
- ذخیره به‌صورت `draft` ممکن باشد؛ «انتشار» وضعیت را `active` می‌کند.
- پس از ساخت → مستقیم به تب «دعوت» کلاس با لینک آماده.

### ۶.۵ جزئیات کلاس (گام ۸+ — تب‌ها گسترش می‌یابند)
تب‌های فعلی: دانش‌آموزان، دعوت، ویرایش. تب‌های هدف فاز ۱:

| تب | محتوا | گام |
|---|---|---|
| نمای کلی | خلاصه‌ی زمان‌بندی، ظرفیت، شهریه، لینک دعوت برجسته | ۸ |
| دانش‌آموزان | لیست ثبت‌نامی‌ها + افزودن از روستر (هست) | ۸ |
| حضور | لیست جلسات؛ هر جلسه → صفحه‌ی ثبت حضور | ۱۱ |
| تکالیف | لیست تکالیف + «تکلیف جدید»؛ شمارنده‌ی تحویل/بررسی | ۱۲ |
| پرداخت | جدول شهریه‌ی دانش‌آموزان: مبلغ، پرداخت‌شده، مانده، وضعیت | ۱۵ |
| دعوت | لینک کپی‌شدنی + toggle فعال/باطل + تاریخچه‌ی پیوستن (هست) | ۹ |
| ویرایش | فرم کلاس (هست) | ۸ |

در موبایل تب‌ها اسکرول افقی؛ در دسکتاپ کامل.

### ۶.۶ دانش‌آموزان مربی (گام ۷ — موجود)
- تب فعال/بایگانی + جدول (هست). در موبایل جدول → لیست کارتی (نام+آواتار، تلفن، یادداشت، دکمه‌ی آرشیو).
- افزودن با ایمیل در Dialog (هست) + آینده: دعوت با لینک برای دانش‌آموز بدون حساب.
- **`/students/[id]` جدید:** پروفایل دانش‌آموز — کلاس‌ها، نرخ حضور، تکالیف اخیر، وضعیت پرداخت، یادداشت، تاریخچه. (CLAUDE.md §5.2: view/edit/archive/history)

### ۶.۷ تقویم (گام ۱۰)
- نماهای روز/هفته/ماه (تب `<Tabs>` مشابه style-guide فعلی).
- موبایل پیش‌فرض «هفته» به‌صورت لیست تایم‌لاین؛ دسکتاپ گرید هفتگی.
- رنگ رویداد بر اساس کلاس؛ کلیک → جزئیات جلسه.
- **جلسات خصوصی (CLAUDE.md §5.2):** جریان پیشنهاد → پذیرش/رد → تأیید در Sheet؛ در تقویم با استایل «در انتظار» (خط‌چین/`muted`) تا تأیید.
- **والد:** تقویم خانوادگی همه‌ی فرزندان با هم، فیلتر پرِ فرزند.

### ۶.۸ حضور و غیاب (گام ۱۱)
- **صفحه‌ی ثبت حضور یک جلسه:** لیست دانش‌آموزان؛ هر ردیف یک سگمنت ۴تایی: حاضر / غایب / تأخیر / موجه (رنگ‌های معنایی). پیش‌فرض همه «حاضر»، مربی فقط استثناها را می‌زند → کمترین کلیک.
- دکمه‌ی «ثبت همه» بالای لیست. جمع‌بندی: نرخ حضور جلسه و نرخ حضور کل کلاس.
- Optimistic + toast. حالت خالی: «هنوز جلسه‌ای برای این کلاس تعریف نشده».

### ۶.۹ تکالیف (گام ۱۲)
- **ساخت تکلیف (Sheet/صفحه):** عنوان، شرح، مهلت، پیوست اختیاری، انتخاب کلاس.
- **لیست تکالیف کلاس:** وضعیت‌ها assigned/submitted/reviewed/late/missing با Badge؛ شمارنده‌ی «X از Y تحویل داده».
- **بازبینی:** لیست تحویل‌ها → باز کردن یک تحویل → مشاهده‌ی محتوا/پیوست + فیلد بازخورد + نمره → «ثبت بازبینی».
- **سمت دانش‌آموز:** `/homework` لیست همه‌ی کلاس‌ها با مهلت و وضعیت؛ `/homework/[id]` مشاهده + فرم تحویل (متن/فایل) + پس از بازبینی: نمره و بازخورد.

### ۶.۱۰ نمرات (گام ۱۳)
- انواع: عددی / حرفی / قبول-مردود / بازخورد متنی (CLAUDE.md §5.2). کامپوننت `<GradeInput type>`.
- نمای مربی: در دل بازبینی تکلیف + یک تب «نمرات» سطح کلاس (ماتریس دانش‌آموز × تکلیف، در موبایل پرِ دانش‌آموز).
- نمای دانش‌آموز: «نمرات اخیر» در خانه + فهرست کامل در کلاس.

### ۶.۱۱ پیام‌ها (گام ۱۴)
- **لایه‌ی ابزار، نه شبکه‌ی اجتماعی** (CLAUDE.md §5.2). دو نوع: اعلان کلاس (یک‌طرفه از مربی) + گفت‌وگوی مستقیم مربی ↔ دانش‌آموز/والد.
- `/messages`: لیست گفت‌وگوها (آواتار، نام، آخرین پیام، زمان، Badge خوانده‌نشده).
- `/messages/[id]`: حباب‌های پیام (فرستنده راست/چپ بر پایه‌ی RTL و «خودی/غیرخودی»)، وضعیت sent/delivered/read، ورودی پایین ثابت.
- بدون emoji-reaction، بدون استوری، بدون گروه‌چت آزاد. اعلان کلاس فقط از سمت مربی ساخته می‌شود.

### ۶.۱۲ پرداخت‌های پایه (گام ۱۵)
- **بدون درگاه، بدون حسابداری** (CLAUDE.md §5.2). فقط رهگیری.
- در تب پرداخت کلاس: هر دانش‌آموز یک ردیف — مبلغ شهریه، پرداخت‌شده، مانده (محاسبه‌شده)، وضعیت `paid/partially paid/unpaid/overdue` با رنگ معنایی.
- اکشن: «ثبت پرداخت» در Sheet (مبلغ، تاریخ، یادداشت). سررسید گذشته → خودکار `overdue`.
- نمای دانش‌آموز/والد: کارت «وضعیت شهریه» فقط‌خواندنی با مبلغ مانده و سررسید.

### ۶.۱۳ داشبورد دانش‌آموز (گام ۱۶)
- **هدف:** «امروز چه دارم؟» کلاس بعدی، کلاس‌های امروز، تکالیف در انتظار، نمرات اخیر، پیام خوانده‌نشده.
- کارت «کلاس بعدی» برجسته با زمان و شمارش معکوس نرم.
- حالت خالی (تازه عضو، بدون کلاس): «با لینک دعوت مربی‌ات به اولین کلاس بپیوند».

### ۶.۱۴ داشبورد والد (گام ۱۷)
- سوییچر فرزند بالای صفحه (آواتارها). زیر آن = داشبورد همان فرزند (بازاستفاده از ویجت‌های دانش‌آموز).
- تقویم خانوادگی ترکیبی. کارت جمع‌بندی هر فرزند: کلاس امروز، تکلیف عقب‌افتاده، شهریه‌ی مانده.
- `/children` مدیریت فهرست فرزندان.

### ۶.۱۵ اعلان‌ها (گام ۱۸)
- آیکون زنگ در Header همه‌ی نقش‌ها → Sheet لیست اعلان (خوانده/نخوانده، لینک به منبع).
- درون‌اپ در فاز ۱؛ سرویس `notifications` جداکوپل تا بعداً push/email اضافه شود.
- تنظیم ساده‌ی خاموش/روشن هر دسته در «بیشتر».

### ۶.۱۶ صفحات عمومی و دعوت (گام ۹ — موجود)
- `/join/class/[id]` (هست): پیش‌نمایش کلاس + «ثبت‌نام و پیوستن / ورود و پیوستن»، حفظ `?next=`، auto-join پس از احراز، صفحه‌ی موفقیت. فقط پولیش بصری با کامپوننت‌های جدید.
- لندینگ مهمان `/`: ارزش‌پیشنهادی کوتاه + «ثبت‌نام / ورود». **بدون** جست‌وجو/مرور عمومی کلاس‌ها (CLAUDE.md §8.1 — Discovery در فاز ۱ ساخته نمی‌شود).

## ۸. PWA و آفلاین

- Manifest و Service Worker (Serwist) هست. افزودن: آیکون‌های کامل (۱۹۲/۵۱۲/maskable)، `theme_color` هماهنگ با توکن، اسکرین‌شات برای نصب.
- **پوسته‌ی کش‌شده:** `AppShell` و مسیرهای اصلی offline-first؛ داده‌ی API با Stale-While-Revalidate.
- **تخریب محترمانه:** بنر «آفلاین هستید — اطلاعات ممکن است به‌روز نباشد»؛ اکشن‌های نوشتنی در آفلاین غیرفعال با راهنما.
- Prompt نصب در تب «بیشتر» (نه مزاحم/خودکار).

## ۹. دسترس‌پذیری و RTL — چک‌لیست تحویل

- [ ] کنتراست متن ≥ ۴.۵:۱، عناصر بزرگ ≥ ۳:۱ (روشن و تاریک).
- [ ] هدف لمسی ≥ ۴۴×۴۴px؛ فاصله‌ی کافی بین اکشن‌ها.
- [ ] حلقه‌ی فوکوس دیداری روی همه‌ی عناصر تعاملی (`--ring`).
- [ ] پیمایش کامل با صفحه‌کلید؛ ترتیب Tab منطقی در RTL.
- [ ] `aria-live` برای toast، شمارنده‌ها و تغییر وضعیت (حضور، پرداخت).
- [ ] برچسب `Label`↔`id`، `aria-describedby` برای خطای فیلد.
- [ ] آیکون‌های جهت‌دار mirror؛ `ms/me`، `text-start/end`، بدون `left/right` سخت.
- [ ] اعداد فارسی در نمایش، لاتین در ورودی فنی؛ فرمت تاریخ `fa-IR`.
- [ ] تصاویر `alt`؛ آواتار fallback حرف اول نام.
- [ ] `prefers-reduced-motion` رعایت شود.

## ۱۰. لحن و محتوای فارسی

- محاوره‌ی محترمانه، کوتاه، بدون اصطلاح فنی. «کلاس بساز» نه «ایجاد موجودیت کلاس».
- خطاها راه‌حل‌محور: «این ایمیل حساب دانش‌آموز ندارد. از او بخواهید اول ثبت‌نام کند.»
- حالت خالی تشویقی، نه سرزنشی.
- برچسب اکشن = فعل + مفعول: «افزودن دانش‌آموز»، «ثبت حضور»، «کپی لینک دعوت».
- واژه‌نامه‌ی ثابت در `lib/status.ts` و `lib/labels.ts` (حاضر/غایب/تأخیر/موجه، پرداخت‌شده/جزئی/پرداخت‌نشده/سررسیدگذشته، پیش‌نویس/فعال/تکمیل/لغو/بایگانی).

## ۱۲. تحویل‌دادنی‌ها و گام بعد

**تحویل‌دادنی‌های طراحی:**
- این سند + `/design-system` زنده (توکن‌ها، Primitives، چهار حالت، روشن/تاریک).
- کیت Layout Primitives و کامپوننت‌های بخش ۷ در `src/components/layout` و `src/components/*`.
- واژه‌نامه‌ی `lib/status.ts` + `lib/labels.ts`.
- چک‌لیست دسترس‌پذیری/RTL بخش ۹ به‌عنوان معیار پذیرش هر PR رابط.

**تعریف «انجام‌شده» برای هر صفحه (CLAUDE.md §13):**
`UI + API + DB + Authorization + Validation + Loading + Empty + Error + Mobile responsive + Tests`.

**گام بعدی پیشنهادی:** اجرای **موج ۰ (پایه)** — بدون آن هر ماژول بعدی چیدمان و حالت‌ها را دوباره کپی می‌کند.
